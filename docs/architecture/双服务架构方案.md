## 1. 设计背景

### 1.1 为什么选择双服务架构

云盘智能体应用涉及两类核心能力：
- **业务逻辑能力**：文件管理、用户认证、权限控制、WebDAV/S3协议兼容
- **AI处理能力**：文件理解、语义检索、内容生成、RAG问答

这两类能力对技术栈和运行环境的要求不同：

| 维度 | 业务逻辑 | AI处理 |
|------|---------|--------|
| 语言生态 | Java生态成熟(Spring Boot, JPA, Spring Security) | Python生态丰富(LangChain, PyTorch, Transformers) |
| 性能要求 | IO密集型，高并发请求 | 计算密集型，GPU加速 |
| 扩展性 | 水平扩展，无状态 | 需GPU资源，独立扩缩容 |
| 工具链 | Maven/Gradle, JUnit | pip, Conda, pytest |

因此，采用**双服务架构**，将业务逻辑和AI处理分离为两个独立的服务。

## 2. 服务定义

### 2.1 Java后端服务

| 属性 | 说明 |
|------|------|
| **服务名** | `nebulamind-backend` |
| **技术栈** | Spring Boot 3.2.x, Java 21 |
| **端口** | 8080 |
| **副本数** | 2-4 (生产环境) |
| **资源** | CPU: 4核, 内存: 8GB |

**职责**：
- 用户认证授权（JWT + RBAC）
- 文件管理（上传、下载、列表、删除、分片上传）
- 安全管控（敏感检测触发、加密解密、权限校验）
- 版本管理与云存储对接
- 协议兼容（WebDAV/S3协议适配）
- 消息队列发送（文件上传/删除事件）
- 调用Python AI服务（搜索、问答、生成）
- 缓存管理（Redis）

**不负责**：
- 不负责 RAG 向量化与 Milvus 索引管理（由 Python AI 服务承担）
- 图片/PPT 视觉理解、敏感检测等场景会通过 MaasApiClient 直连元景 MaaS
- 不向前端暴露 AI 服务地址（统一走 Java 后端入口）

### 2.2 Python AI服务

| 属性 | 说明 |
|------|------|
| **服务名** | `nebulamind-ai-service` |
| **技术栈** | Python 3.10+, FastAPI, 自研 RAG（pymilvus + OpenAI 兼容 SDK） |
| **端口** | 8081 |
| **副本数** | 2-4 (生产环境，建议GPU) |
| **资源** | CPU: 8核, 内存: 16GB, GPU: 可选 |

**职责**：
- 文件理解（文件类型识别、内容提取、标签生成、智能分类）
- 语义检索（查询理解、向量化、混合检索、重排序）
- 内容生成（摘要生成、报告生成、PPT生成）
- RAG问答（文档问答、跨文件问答）
- 安全识别（敏感信息识别、Prompt注入防护）
- 消息队列消费（文件上传/删除事件处理）
- 向量索引管理（Milvus增删改查）

**不负责**：
- 不管理用户会话和认证
- 不处理文件上传下载
- 不直接向前端提供业务 API（由 Java 后端统一入口调用）

## 3. 通信协议

### 3.1 同步通信：REST API

Java后端通过HTTP REST API调用Python AI服务。

**API前缀**：`/api/v1/`

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 文件分类 | POST | `/api/v1/classify` | 文件类型识别、标签生成、智能分类 |
| 语义搜索 | POST | `/api/v1/search` | 自然语言搜索文件 |
| 文档问答 | POST | `/api/v1/qa` | 基于文档问答 |
| 跨文件问答 | POST | `/api/v1/qa/cross` | 跨文件问答 |
| 生成摘要 | POST | `/api/v1/generate/summary` | 文档摘要生成 |
| 内容提炼 | POST | `/api/v1/generate/extract` | 关键信息提取 |
| 生成报告 | POST | `/api/v1/generate/report` | 分析报告生成 |
| 生成PPT | POST | `/api/v1/generate/ppt` | PPT 大纲生成 |
| 格式转换 | POST | `/api/v1/generate/convert` | txt/md → docx 等格式转换 |
| 敏感检测 | POST | `/api/v1/sensitive/detect` | 敏感内容识别 |
| 敏感脱敏 | POST | `/api/v1/sensitive/mask` | 敏感内容脱敏 |
| 服务状态 | GET | `/health`、`/api/v1/stats` | 健康检查与调用统计 |

### 3.2 异步通信：RabbitMQ

Java后端通过RabbitMQ发送文件事件消息，Python AI服务消费处理。

**Exchange配置**：

| 属性 | 值 |
|------|-----|
| Exchange名称 | `nebulamind.exchange` |
| Exchange类型 | `direct` |
| 持久化 | 是 |

**Queue配置**：

| Queue名称 | Binding Key | 消费者 | 说明 |
|-----------|------------|--------|------|
| `nebulamind.file.upload` | `file.upload` | Python AI | 文件上传处理队列 |
| `nebulamind.file.delete` | `file.delete` | Python AI | 文件删除处理队列 |
| `nebulamind.file.processed` | `file.processed` | 暂未消费 | 已声明，待接入处理结果队列 |

Python AI 消费 `file.upload` / `file.delete` 后，通过 HTTP 回调 `/api/v1/files/{fileId}/process-callback`（请求头携带 `X-Internal-Api-Key`）通知 Java 后端更新文件状态。

### 3.3 实时通信：WebSocket/SSE

Java后端通过SSE(Server-Sent Events)向前端推送实时消息。

| 场景 | 协议 | 说明 |
|------|------|------|
| AI处理进度推送 | SSE | 文件上传后AI处理进度 |
| 流式问答响应 | SSE | 文档问答的流式输出 |
| 系统通知 | SSE | 文件处理完成通知 |

## 5. 容错与降级策略

### 5.1 服务降级

| 场景 | 降级策略 | 用户体验 |
|------|---------|---------|
| Python AI服务不可用 | Java后端返回缓存结果或错误提示 | 搜索/问答功能不可用，文件管理正常 |
| MaaS API限流/超时 | 重试3次 → 降级到备用模型 → 返回错误 | 响应延迟增加或功能受限 |
| RabbitMQ不可用 | 本地内存队列暂存（设计策略，当前代码未实现） | 文件处理延迟，不影响上传 |
| Milvus不可用 | 降级到BM25全文检索 | 搜索精度降低，功能可用 |

### 5.2 重试策略

| 组件 | 重试次数 | 重试间隔 | 退避策略 |
|------|---------|---------|---------|
| Python AI服务调用 | 3次 | 1s, 2s, 4s | 指数退避 |
| MaaS API调用 | 3次 | 2s, 4s, 8s | 指数退避 + 抖动 |
| RabbitMQ消息消费 | 设计目标 5 次 | 固定30s | 死信队列（当前 worker 仅 ack/nack） |

### 5.3 熔断机制

Java后端调用Python AI服务时，采用熔断器模式：

```
正常状态 ──→ 失败率>50%(10s窗口) ──→ 熔断状态(30s) ──→ 半开状态(5s)
                                                    │
                                             ┌──────┴──────┐
                                             ↓              ↓
                                          成功            失败
                                       恢复正常       再次熔断
```

## 6. 安全通信

### 6.1 内部通信安全

| 通信方式 | 安全措施 |
|---------|---------|
| Java后端 ↔ Python AI (HTTP) | `X-API-Key` 认证 + 内网通信（生产 Compose 网络） |
| Java后端 ↔ RabbitMQ | Vhost隔离 + 账号密码认证 |
| Python AI ↔ RabbitMQ | Vhost隔离 + 账号密码认证 |
| 所有服务 ↔ 数据库 | 账号密码认证 + 网络策略限制 |

### 6.2 内部Token管理

```yaml
# 内部服务通信密钥
ai-service:
  api-key: ${AI_SERVICE_API_KEY}  # AI 服务校验请求头 X-API-Key
  # 密钥定期轮换，由运维工程师管理

backend:
  internal-api-key: ${INTERNAL_API_KEY}  # 后端校验回调请求头 X-Internal-Api-Key
```
