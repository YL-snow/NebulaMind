## 3. 数据库选型

### 3.1 关系数据库：PostgreSQL 15.x

| 对比项 | PostgreSQL 15.x | MySQL 8.x | 说明 |
|--------|----------------|-----------|------|
| JSON支持 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | PostgreSQL支持JSONB索引 |
| 全文检索 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | 内置BM25全文检索 |
| 扩展性 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | PG支持自定义类型、插件 |
| 并发控制 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | MVCC实现 |
| 开源协议 | PostgreSQL License | GPL | 更友好 |

**选型理由**：
- 原生JSONB类型支持，适合存储AI分析结果、文件元数据等半结构化数据
- 内置BM25全文检索，可作为语义检索的补充（混合检索策略）
- 支持向量扩展（pgvector），可作为Milvus的轻量替代方案
- 与[技术方案](../云盘智能体应用开发技术方案.md#L409)一致

### 3.2 向量数据库：Milvus 2.4.x

| 对比项 | Milvus 2.4.x | pgvector | Qdrant | Pinecone |
|--------|--------------|----------|--------|---------|

| 开源 | 是 | 是 | 是 | 否 |
| 亿级向量 | 支持 | 不支持 | 支持 | 支持 |

- 开源且社区活跃，支持自托管部署
- 高性能向量检索，支持亿级规模
- 支持标量过滤+向量检索的混合查询
- 与[技术方案](../云盘智能体应用开发技术方案.md#L409)一致

### 3.3 缓存：Redis 7.x

| 对比项 | Redis 7.x | Memcached | 说明 |
|--------|-----------|-----------|------|

## 4. 消息队列选型

### 4.1 RabbitMQ 3.12.x

| 对比项 | RabbitMQ 3.12.x | Apache Kafka | Redis Stream |
|--------|----------------|-------------|-------------|
| 消息模型 | 队列/Exchange | Topic/Partition | Stream |
| 消息确认 | 支持 | 支持 | 支持 |
| 死信队列 | 支持 | 需自定义 | 需自定义 |
| 延迟消息 | 支持(插件) | 不支持 | 不支持 |
| 运维复杂度 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| 吞吐量 | 万级/秒 | 百万级/秒 | 万级/秒 |
| 消息持久化 | 支持 | 支持 | 支持 |

**选型理由**：
- 消息确认机制完善，适合文件处理场景（确保消息不丢失）
- 支持死信队列，处理失败消息（如AI处理失败后重试）
- 路由灵活（Topic Exchange），支持多消费者模式
- 运维简单，适合中小规模项目
- 文件处理场景的吞吐量需求（万级/秒），RabbitMQ完全满足

### 4.2 消息队列拓扑

```
Exchange: nebulamind.file (topic)
    │
    ├── routing key: "file.uploaded"  → Queue: ai.file.upload  → Python AI
    ├── routing key: "file.deleted"   → Queue: ai.file.delete  → Python AI
    ├── routing key: "file.updated"   → Queue: ai.file.update  → Python AI
    └── routing key: "ai.*"           → Queue: backend.callback → Java后端
```

| 对比项 | MinIO | Ceph RGW | 直接使用云盘API |
|--------|-------|----------|----------------|
| 部署复杂度 | ⭐⭐⭐⭐⭐ (低) | ⭐⭐ (高) | ⭐⭐⭐⭐⭐ (无需部署) |

## 6. AI框架选型

### 6.1 RAG 实现：自研轻量流程（FastAPI + OpenAI 兼容 SDK + pymilvus）

| 对比项 | 自研流程 | LangChain | LlamaIndex |
|--------|---------|-----------|------------|
| RAG支持 | 按业务可控实现 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 依赖数量 | 少（httpx/openai/pymilvus） | 多 | 多 |
| 文档加载器 | 自研 FileParser | ⭐⭐⭐⭐⭐ (100+) | ⭐⭐⭐⭐ (50+) |
| 可调试性 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| 学习曲线 | 适中（贴近业务） | ⭐⭐⭐ (中) | ⭐⭐⭐⭐ (低) |
| 社区活跃度 | - | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |

**选型理由**：
- 当前 AI 服务共 11 个业务端点 + 5 个辅助端点（`/`、health/stats/logs/prompts），按 `file_understanding / semantic_search / rag_qa / content_generation / sensitive_detector` 自研分层实现，未引入 LangChain 依赖
- OpenAI 兼容 SDK 直连元景 MaaS，调用链短，限流与降级逻辑集中在 `core/llm_client.py`
- 向量索引与检索使用 pymilvus，RAG 链路可控，便于讲解与后续扩展

### 6.2 AI能力来源：元景MaaS云API

| 对比项 | 元景MaaS云API | 本地部署模型 | 其他云API |
|--------|--------------|------------|----------|
| 部署成本 | ⭐⭐⭐⭐⭐ (低) | ⭐⭐ (高，需GPU) | ⭐⭐⭐⭐ |
| 维护成本 | ⭐⭐⭐⭐⭐ (无) | ⭐⭐ (高) | ⭐⭐⭐⭐ |
| 调用延迟 | ⭐⭐⭐ (中) | ⭐⭐⭐⭐ (低) | ⭐⭐⭐ |
| 可定制性 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| 数据隐私 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

**选型理由**：
- 无需GPU资源，部署成本低
- 零维护成本，由联通运维
- API兼容OpenAI标准，对接方便
- 与[技术方案](../云盘智能体应用开发技术方案.md#L118)一致
