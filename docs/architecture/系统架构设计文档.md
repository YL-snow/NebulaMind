## 2. 双服务架构设计

### 2.1 服务职责边界

| 服务 | 技术栈 | 职责 | 不负责 |
|------|-------|------|-------|
| **Java后端服务** | Spring Boot 3.2.x | 文件管理CRUD、用户认证授权、RBAC权限、安全管控、WebDAV/S3协议兼容、消息队列发送、文件上传下载、版本管理 | 不直接调用AI模型 |
| **Python AI服务** | Python 3.11+, LangChain | 文件理解(分类/标签/摘要)、语义检索(Embedding/Reranker)、内容生成(报告/PPT)、RAG问答、敏感信息识别 | 不管理用户会话 |

### 2.2 服务调用关系

```
┌───────────────┐         ┌───────────────────┐         ┌────────────────┐
│   前端/客户端   │  HTTP   │   Java后端服务     │  HTTP   │  Python AI服务  │
│               │ ──────→ │                   │ ──────→ │                │
│               │         │  (API Gateway)    │         │  (AI处理引擎)   │
│               │ ←────── │                   │ ←────── │                │
│               │  JSON   │                    │  JSON   │                │
└───────────────┘         └───────────────────┘         └────────────────┘
                                    │                          │
                                    │ RabbitMQ                 │ RabbitMQ
                                    │ (文件上传/删除消息)        │ (消费消息)
                                    ▼                          ▼
                           ┌───────────────────┐         ┌────────────────┐
                           │     RabbitMQ      │←────────│  AI处理结果     │
                           │  (消息队列)        │─────────→│  (回调通知)     │
                           └───────────────────┘         └────────────────┘
```

**关键规则**：
- 前端/客户端 **只与Java后端服务通信**，不直接调用Python AI服务
- Java后端服务通过 **REST API + JSON** 调用Python AI服务
- 上传/删除文件时，Java后端向 **RabbitMQ** 发送消息，Python AI服务消费消息进行处理
- Python AI服务处理完成后，通过 **回调接口** 通知Java后端更新文件状态

### 2.3 跨语言通信协议

| 协议 | 用途 | 数据格式 | 认证方式 |
|------|------|---------|---------|
| **REST API** | 同步调用（搜索、问答、生成） | JSON | 内部Token |
| **RabbitMQ** | 异步消息（文件处理、索引更新） | JSON | Vhost认证 |
| **WebSocket/SSE** | 实时推送（AI处理进度、流式响应） | JSON | JWT Token |

## 5. 消息队列设计

### 5.1 消息队列拓扑

```
┌─────────────────────────────────────────────────────────────────┐
│                        RabbitMQ                                  │
│                                                                  │
│  Exchange: nebulamind.file                                      │
│  Type: topic                                                     │
│                                                                  │
│  ┌─────────────────────────────────────────────────────────────┐│
│  │                    Binding Keys                              ││
│  │                                                              ││
│  │  file.uploaded   → Queue: ai.file.upload   → Python AI消费   ││
│  │  file.deleted    → Queue: ai.file.delete   → Python AI消费   ││
│  │  file.updated    → Queue: ai.file.update   → Python AI消费   ││
│  │  ai.processing   → Queue: backend.callback  → Java后端消费   ││
│  │  ai.completed    → Queue: backend.callback  → Java后端消费   ││
│  │  ai.failed       → Queue: backend.callback  → Java后端消费   ││
│  └─────────────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 消息体格式

```json
{
  "eventId": "uuid",
  "eventType": "file.uploaded",
  "timestamp": "2026-07-11T10:00:00Z",
  "source": "java-backend",
  "data": {
    "fileId": "file-uuid",
    "fileName": "document.pdf",
    "filePath": "/user/uploads/document.pdf",
    "fileSize": 1024000,
    "mimeType": "application/pdf",
    "fileHash": "sha256-hash",
    "userId": "user-uuid",
    "uploadTime": "2026-07-11T10:00:00Z"
  }
}
```

### 5.3 消息类型定义

| 消息类型 | 发送方 | 消费者 | 触发条件 | 处理内容 |
|---------|-------|--------|---------|---------|
| `file.uploaded` | Java后端 | Python AI | 文件上传完成 | 解析文件、生成向量索引 |
| `file.deleted` | Java后端 | Python AI | 文件删除 | 删除向量索引 |
| `file.updated` | Java后端 | Python AI | 文件内容更新 | 重新解析、更新向量索引 |
| `ai.processing` | Python AI | Java后端 | AI开始处理 | 更新文件状态为"处理中" |
| `ai.completed` | Python AI | Java后端 | AI处理完成 | 更新文件状态为"已完成"，保存AI分析结果 |
| `ai.failed` | Python AI | Java后端 | AI处理失败 | 更新文件状态为"处理失败"，记录错误信息 |

## 8. 关键技术决策

### 8.1 架构决策记录

| 决策ID | 决策项 | 选择方案 | 被淘汰方案 | 理由 |
|--------|-------|---------|-----------|------|
| ADR-001 | 后端架构 | 双服务(Java+Python) | 单体全栈 | AI处理与业务逻辑分离，独立扩展 |
| ADR-002 | 通信协议 | REST API + JSON | gRPC/GraphQL | 简单成熟，团队熟悉，调试方便 |
| ADR-003 | 异步处理 | RabbitMQ | Kafka/Redis Stream | 轻量级，运维简单，消息确认机制完善 |
| ADR-004 | 向量数据库 | Milvus | Pinecone/Qdrant | 开源，社区活跃，支持大规模数据 |
| ADR-005 | 文件存储 | MinIO | 直接云盘存储 | 支持S3协议，本地缓存加速 |
| ADR-006 | AI能力来源 | 元景MaaS云API | 本地部署模型 | 无需GPU，成本可控，维护简单 |
| ADR-007 | 容器编排 | Kubernetes | Docker Compose | 生产级编排，弹性伸缩，滚动更新 |

### 8.2 日志系统设计

#### 8.2.1 日志分类与存储

| 日志类型 | 框架 | 输出目标 | 保留周期 | 说明 |
|---------|------|---------|---------|------|
| **应用日志** | SLF4J + Logback | 控制台(dev) + 滚动文件(prod) | 30天 | 记录请求处理、业务逻辑、异常信息 |
| **AI调用日志** | 自定义AOP + 数据库 | 数据库 + 文件 | 90天 | 记录模型调用、Token用量、延迟、成功率 |
| **安全审计日志** | 自定义AOP + 数据库 | 数据库 | 180天 | 记录登录、权限变更、敏感文件操作、删除操作 |

| 生产(prod) | WARN | WARN | INFO |

### 8.3 架构约束

| 约束 | 说明 | 来源 |
|------|------|------|
| Java后端不直接调用AI模型 | 所有AI能力通过Python AI服务代理 | 架构分层原则 |
| 前端只与Java后端通信 | 统一API入口，简化安全策略 | 安全架构要求 |
| 文件上传必须异步处理 | 避免阻塞主线程，提升用户体验 | 性能需求 |
| 敏感信息必须本地脱敏 | 不上传原始敏感内容到AI模型 | 数据安全要求 |
| 所有API调用必须记录日志 | 用于审计、成本分析、问题排查 | 运维要求 |
