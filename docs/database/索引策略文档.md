### 1.2 索引策略原则

| 原则 | 说明 |
|------|------|
| **高频查询优先** | 用户查询、文件列表、搜索等高频操作用索引覆盖 |
| **唯一约束用唯一索引** | 用户名、邮箱、Token哈希等必须唯一 |
| **部分索引减少开销** | 只对活跃数据建索引（如 active用户、未过期Token） |
| **GIN索引支持JSONB** | tags、metadata等JSONB字段用GIN索引加速 |
| **全文检索用tsvector** | 使用 PostgreSQL 内置的 BM25 风格全文检索 |
| **复合索引减少回表** | 按查询模式设计复合索引，尽量覆盖查询 |

## 2. 索引详细说明

### 2.1 users（用户表）

| 索引名 | 类型 | 字段 | 是否唯一 | 说明 |
|--------|------|------|:-------:|------|
| `idx_users_username` | BTREE | username | ✅ | 用户登录查询 |
| `idx_users_email` | BTREE | email | ✅ | 邮箱登录查询 |
| `idx_users_status` | BTREE (部分) | status WHERE status='active' | ❌ | 活跃用户查询，减少索引大小 |

**查询场景分析**：
- 用户登录：`SELECT * FROM users WHERE username = ?` → 命中 `idx_users_username`
- 邮箱注册：`SELECT * FROM users WHERE email = ?` → 命中 `idx_users_email`
- 管理员列表：`SELECT * FROM users WHERE status = 'active'` → 命中 `idx_users_status`

### 2.2 files（文件表）

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| `idx_files_user_id` | BTREE | user_id | 用户文件列表查询 |
| `idx_files_parent_id` | BTREE | parent_id | 目录浏览查询 |
| `idx_files_hash` | BTREE | hash | 重复检测查询 |
| `idx_files_status` | BTREE | status | 状态筛选 |
| `idx_files_ai_status` | BTREE | ai_status | AI处理状态查询 |
| `idx_files_category` | BTREE | category | 分类筛选 |
| `idx_files_created_at` | BTREE (DESC) | created_at | 时间排序，最新文件优先 |
| `idx_files_name_trgm` | GIN | name gin_trgm_ops | 文件名模糊搜索（`%keyword%`） |
| `idx_files_tags_gin` | GIN | tags | JSONB标签搜索（`tags ? '报告'`） |

**查询场景分析**：

| 查询 | SQL | 命中索引 |
|------|-----|---------|
| 用户文件列表 | `WHERE user_id = ? ORDER BY created_at DESC` | `idx_files_user_id` + `idx_files_created_at` |
| 目录浏览 | `WHERE parent_id = ?` | `idx_files_parent_id` |
| 重复检测 | `WHERE hash = ?` | `idx_files_hash` |
| AI处理中列表 | `WHERE ai_status = 'processing'` | `idx_files_ai_status` |
| 按分类筛选 | `WHERE category = ?` | `idx_files_category` |
| 文件名搜索 | `WHERE name LIKE '%关键词%'` | `idx_files_name_trgm` |
| 标签筛选 | `WHERE tags ? '财务'` | `idx_files_tags_gin` |

### 2.3 file_contents（文件内容分片表）

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| `idx_file_contents_file_id` | BTREE | file_id | 按文件查询分片 |
| `idx_file_contents_file_chunk` | BTREE (UNIQUE) | (file_id, chunk_index) | 分片序号唯一约束 |
| `idx_file_contents_fts` | GIN | to_tsvector('simple', chunk_content) | **BM25全文检索** |

**BM25全文检索索引配置**：

```sql
-- 创建 tsvector 全文检索索引 (BM25 风格)
-- 'simple' 配置适用于英文，中文需要配置中文分词器
CREATE INDEX idx_file_contents_fts ON file_contents
    USING GIN (to_tsvector('simple', coalesce(chunk_content, '')));

-- 使用示例: 搜索文档内容
-- 1. 普通搜索
SELECT * FROM file_contents
WHERE to_tsvector('simple', chunk_content) @@ plainto_tsquery('simple', '销售数据');
-- 2. 加权搜索
SELECT * FROM file_contents
WHERE to_tsvector('simple', chunk_content) @@ to_tsquery('simple', '销售 & 数据');
-- 3. 按相关性排序
SELECT file_id, chunk_index, chunk_content,
       ts_rank(to_tsvector('simple', chunk_content), plainto_tsquery('simple', '销售数据')) AS rank
FROM file_contents
WHERE to_tsvector('simple', chunk_content) @@ plainto_tsquery('simple', '销售数据')
ORDER BY rank DESC;
```

### 2.4 semantic_indexes（语义索引表）

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| `idx_semantic_indexes_file_id` | BTREE | file_id | 按文件查询索引 |
| `idx_semantic_indexes_file_chunk` | BTREE (UNIQUE) | (file_id, chunk_index) | 分片序号唯一约束 |
| `idx_semantic_indexes_fts` | GIN | to_tsvector('simple', chunk_text) | **BM25全文检索（混合检索用）** |
| `idx_semantic_indexes_metadata_gin` | GIN | metadata | 元数据搜索 |

**混合检索策略**：

```
用户查询
    │
    ├──→ 语义检索 (Milvus)：query_embedding → 向量相似度搜索 → 候选集A
    │
    ├──→ BM25检索 (PostgreSQL)：to_tsvector @@ to_tsquery → 候选集B
    │
    └──→ 结果合并 (Reranker)：A ∪ B → 重排序 → 最终结果
```

### 2.5 ai_call_logs（AI调用日志表）

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| `idx_ai_call_logs_request_id` | BTREE | request_id | 请求追踪查询 |
| `idx_ai_call_logs_module` | BTREE | module | 按模块统计 |
| `idx_ai_call_logs_model` | BTREE | model | 按模型统计 |
| `idx_ai_call_logs_user_id` | BTREE | user_id | 按用户统计 |
| `idx_ai_call_logs_file_id` | BTREE | file_id | 按文件查询 |
| `idx_ai_call_logs_created_at` | BTREE (DESC) | created_at | 时间范围查询 |
| `idx_ai_call_logs_failed` | BTREE (部分) | success WHERE success=FALSE | 失败调用查询 |

**部分索引优势**：
- `idx_ai_call_logs_failed` 只索引失败记录，通常失败率 < 5%，索引大小减少 95%

## 3. BM25全文检索配置

### 3.1 中文分词方案

PostgreSQL 原生全文检索支持英文分词，中文需要额外配置。

| 方案 | 安装方式 | 性能 | 准确率 | 推荐 |
|------|---------|:----:|:-----:|:----:|
| **zhparser** | `CREATE EXTENSION zhparser` | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐ **推荐** |
| jieba (pg_jieba) | `CREATE EXTENSION pg_jieba` | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 备选 |
| 简单分词(simple) | 内置，无需安装 | ⭐⭐⭐⭐⭐ | ⭐⭐ | 临时方案 |

**推荐配置（zhparser）**：

```sql
-- 安装 zhparser 扩展
CREATE EXTENSION IF NOT EXISTS zhparser;

-- 创建中文分词配置
CREATE TEXT SEARCH CONFIGURATION chinese (PARSER = zhparser);
ALTER TEXT SEARCH CONFIGURATION chinese
    ADD MAPPING FOR n,v,a,i,e,l WITH simple;

-- 使用中文分词创建全文检索索引
CREATE INDEX idx_file_contents_fts_zh ON file_contents
    USING GIN (to_tsvector('chinese', coalesce(chunk_content, '')));

-- 搜索示例
SELECT * FROM file_contents
WHERE to_tsvector('chinese', chunk_content) @@ plainto_tsquery('chinese', '销售数据');
```

## 4. 性能优化建议

### 4.1 查询优化

| 场景 | 优化 SQL | 说明 |
|------|---------|------|
| 文件列表分页 | `SELECT * FROM files WHERE user_id = ? ORDER BY created_at DESC LIMIT 20` | 使用LIMIT分页，避免OFFSET大偏移 |
| 游标分页 | `SELECT * FROM files WHERE user_id = ? AND created_at < ? ORDER BY created_at DESC LIMIT 20` | 使用游标分页替代OFFSET |
| 封面查询 | `SELECT id, name, file_type, size, created_at FROM files WHERE user_id = ?` | 只查需要的字段，避免SELECT * |
| 批量删除 | `DELETE FROM files WHERE id = ANY(?)` | 使用数组参数，减少SQL执行次数 |

### 4.2 数据库配置建议

| 配置项 | 建议值 | 说明 |
|--------|-------|------|
| `shared_buffers` | 4GB (总内存25%) | 缓存常用数据 |
| `effective_cache_size` | 12GB (总内存75%) | 查询计划器缓存大小 |
| `work_mem` | 64MB | 排序和哈希操作内存 |
| `maintenance_work_mem` | 512MB | 维护操作(索引/VACUUM) |
| `random_page_cost` | 1.1 (SSD) | SSD存储降低随机IO成本 |
| `effective_io_concurrency` | 200 (SSD) | SSD并发IO |
| `max_connections` | 200 | 最大连接数 |
| `default_statistics_target` | 500 | 统计信息采样，提高查询计划质量 |

### 4.3 索引维护策略

| 维护操作 | 频率 | 说明 |
|---------|:----:|------|
| VACUUM | 自动 | PostgreSQL自动清理死元组 |
| ANALYZE | 日 | 更新统计信息，优化查询计划 |
| REINDEX | 周 | 重建索引，减少索引碎片 |
| 清理过期数据 | 日 | 调用 `cleanup_*` 函数清理过期日志 |

### 4.4 分区表建议

对于数据量大的表，建议按时间分区：

**ai_call_logs 按月分区**：

```sql
-- 创建分区表
CREATE TABLE ai_call_logs (
    id UUID NOT NULL,
    created_at TIMESTAMPTZ NOT NULL,
    -- ...其他字段
) PARTITION BY RANGE (created_at);

-- 创建分区
CREATE TABLE ai_call_logs_2026_07 PARTITION OF ai_call_logs
    FOR VALUES FROM ('2026-07-01') TO ('2026-08-01');
CREATE TABLE ai_call_logs_2026_08 PARTITION OF ai_call_logs
    FOR VALUES FROM ('2026-08-01') TO ('2026-09-01');

-- 自动创建分区函数
CREATE OR REPLACE FUNCTION create_ai_call_logs_partition()
RETURNS void AS $$
DECLARE
    partition_date text;
    partition_name text;
BEGIN
    partition_date := to_char(NOW() + INTERVAL '1 month', 'YYYY_MM');
    partition_name := 'ai_call_logs_' || partition_date;
    IF NOT EXISTS (SELECT 1 FROM pg_class WHERE relname = partition_name) THEN
        EXECUTE format(
            'CREATE TABLE %I PARTITION OF ai_call_logs
             FOR VALUES FROM (%L) TO (%L)',
            partition_name,
            date_trunc('month', NOW() + INTERVAL '1 month'),
            date_trunc('month', NOW() + INTERVAL '2 months')
        );
    END IF;
END;
$$ LANGUAGE plpgsql;
```

## 5. 索引性能监控

### 5.1 常用监控查询

```sql
-- 查询索引使用情况
SELECT
    schemaname,
    tablename,
    indexname,
    idx_scan AS index_scans,
    idx_tup_read AS tuples_read,
    idx_tup_fetch AS tuples_fetched
FROM pg_stat_user_indexes
ORDER BY idx_scan DESC;

-- 查询未使用的索引（可能需删除）
SELECT
    schemaname,
    tablename,
    indexname,
    idx_scan
FROM pg_stat_user_indexes
WHERE idx_scan = 0
ORDER BY tablename;

-- 查询表大小和索引大小
SELECT
    relname AS table_name,
    pg_size_pretty(pg_relation_size(relid)) AS table_size,
    pg_size_pretty(pg_indexes_size(relid)) AS index_size
FROM pg_stat_user_tables
ORDER BY pg_relation_size(relid) DESC;
```
