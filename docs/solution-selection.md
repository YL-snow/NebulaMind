# 方案选型记录

## 1. 背景与目标

NebulaMind 需要支持多格式文件理解、检索、问答、内容生成与安全管控。

约束条件：

- 元景 MaaS 接口限流约 5 次 / 分钟，必须做降级与提示。
- 需要支持 Word、PPT、Excel、PDF、图片、压缩包等常见格式。
- 需要支持本地 Docker 部署与云端部署。
- 用户上传的文件可能包含敏感信息，需要安全检测与加密能力。

## 2. 关键选型问题

| 问题 | 候选方案 |
|---|---|
| 文件内容如何理解 | 纯文本解析 / 文本解析 + OCR / 文本解析 + 视觉模型 |
| 文本生成模型 | deepseek-v3_2 等通用文本模型 |
| 图片理解模型 | 元景视觉模型，失败时尝试备用视觉模型 |
| 存储方案 | 本地磁盘 / MinIO / S3 / WebDAV |
| 加密方案 | 服务端加密 / 客户端端到端加密 |
| 压缩包处理 | AI 直接解析 / 提示用户先解压 |

## 3. 候选方案评分

评审维度：格式覆盖度 20%、准确性 25%、成本与限流 15%、实现复杂度 15%、安全合规 15%、可维护性 10%。

| 方案 | 覆盖度 | 准确性 | 成本 | 复杂度 | 安全 | 维护 | 总分 |
|---|---|---|---|---|---|---|---|
| A. 纯文本解析 + 通用模型 | 3 | 3 | 4 | 4 | 3 | 4 | 3.40 |
| B. 多格式解析 + OCR | 4 | 4 | 3 | 3 | 4 | 3 | 3.60 |
| C. 多格式解析 + 文本 / 视觉模型分场景处理 | 5 | 5 | 3 | 4 | 4 | 4 | 4.30 |
| D. 全量多模态大模型统一处理 | 5 | 4 | 2 | 2 | 3 | 3 | 3.35 |

评分按 1-5 打分，示例分数基于当前需求与可用接口约束，用于说明选型过程。

## 4. 选型结论

- 文本类文件使用文本解析 + deepseek-v3_2 生成摘要与问答。
- 图片和图片型 PPT 使用视觉模型；视觉模型不可用时尝试备用模型并返回错误说明。
- 压缩包不直接交给 AI 解析，提示用户先解压后上传。
- 存储支持本地 / MinIO / S3 / WebDAV，默认本地存储，便于演示。
- 加密采用服务端加密与客户端端到端加密两种模式；端到端加密文件服务端无法读取内容，AI 功能返回明确提示。
- 限流采用兜底提示：返回“调用次数已达上限，5 次 / 分钟，请等待后重试”。

## 5. 面试可讲

- 为什么压缩包不让 AI 直接读取：格式复杂、解压风险高、大多数场景收益低。
- 为什么端到端加密文件不能生成摘要：服务端拿不到明文，这是安全与功能之间的取舍。
- 为什么选择“按文件类型分场景处理”而不是单一多模态模型：可用模型、限流和成本约束下，混合方案更稳定。
