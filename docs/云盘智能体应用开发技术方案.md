# 基于大模型技术的云盘智能体应用开发技术方案

## 一、作品简介

### 1.1 项目背景

随着个人与企业云存储数据量持续增长，传统云盘仅具备基础的存储与同步功能，面临以下核心痛点：

| 痛点类别 | 具体表现 | 影响程度 |
|---------|---------|---------|
| 文件检索困难 | 海量文件难以快速定位，依赖手动命名与分类 | 高 |
| 内容利用率低 | 文件内容沉睡，无法主动挖掘价值 | 高 |
| 安全管理薄弱 | 敏感信息泄露风险，权限管理粗放 | 高 |
| 协作效率低下 | 版本管理混乱，信息孤岛严重 | 中 |

### 1.2 项目目标

依托智能体开发平台（联通元景万悟）与大模型的多模态理解与生成能力，将云盘从"被动存储"升级为"主动管理"，打造**懂内容、会整理、能协作**的智能云盘助手。

### 1.3 核心价值主张

- **智能洞察**：自动理解文件内容，主动发现数据价值
- **高效检索**：自然语言语义搜索，跨文件信息整合
- **安全可控**：敏感内容自动识别，隐私保护全覆盖
- **协作赋能**：智能推荐共享策略，提升团队协作效率

#### 5.1.3 万悟大模型API对接

**API端点**：`https://api.wanwu.chinaunicom.cn/v1/chat/completions`

**认证方式**：API Key + JWT Token

**调用示例（Python）**：

```python
import requests
import json

def call_wanwu_llm(prompt, model="wanwu-llm-pro", temperature=0.7):
    headers = {
        "Authorization": "Bearer YOUR_JWT_TOKEN",
        "Content-Type": "application/json"
    }
    payload = {
        "model": model,
        "messages": [
            {"role": "system", "content": "你是一个专业的云盘智能助手，擅长文件理解和信息检索。"},
            {"role": "user", "content": prompt}
        ],
        "temperature": temperature,
        "max_tokens": 4096,
        "stream": False
    }
    response = requests.post(
        "https://api.wanwu.chinaunicom.cn/v1/chat/completions",
        headers=headers,
        json=payload
    )
    return response.json()["choices"][0]["message"]["content"]
```

## 六、RAG技术方案

### 6.1 文档分块策略

#### 6.1.1 分块算法选择

| 算法类型 | 适用场景 | 块大小 | 优缺点 |
|---------|---------|-------|-------|
| 固定长度分块 | 通用文档 | 512-1024 tokens | 简单高效，可能切断语义 |
| 语义分块 | 结构化文档 | 动态 | 保持语义完整性，计算复杂 |
| 段落分块 | 长文档 | 按段落 | 天然语义边界，不均匀 |

**采用方案**：混合分块策略

```
文档 → 段落分割 → 语义检测 → 合并/拆分 → 最终块
```

#### 6.1.2 分块参数配置

| 参数 | 值 | 说明 |
|-----|------|-----|
| 最小块大小 | 256 tokens | 避免过短块 |
| 最大块大小 | 1024 tokens | 控制Embedding成本 |
| 重叠长度 | 128 tokens | 保持上下文连续性 |
| 分块策略 | 语义优先+长度约束 | 平衡语义与效率 |

### 6.2 Embedding模型选型

| 模型 | 维度 | 适用场景 | 调用成本 |
|-----|------|---------|---------|
| wanwu-embedding-v1 | 768 | 通用检索 | 中 |
| bge-large-zh | 1024 | 高精度检索 | 高 |
| text2vec-base-chinese | 768 | 轻量级检索 | 低 |

**采用方案**：默认使用 `wanwu-embedding-v1`，支持动态切换

### 6.3 混合检索策略

#### 6.3.1 BM25+向量混合检索

```
用户查询 → 分词处理 → BM25检索 → 向量检索 → 结果合并 → 重排序 → 返回
```

#### 6.3.2 检索参数配置

| 参数 | 值 | 说明 |
|-----|------|-----|
| BM25结果数 | 20 | 召回候选集 |
| 向量检索结果数 | 15 | 语义候选集 |
| 合并后候选集 | 30 | 去重后 |
| 最终返回数 | 10 | Top-K结果 |

### 6.4 重排序方案

**采用模型**：wanwu-reranker-v1

**重排序流程**：

```
候选文档 → 与查询配对 → Reranker评分 → 按评分排序 → 选择Top-N
```

**调用示例**：

```python
def rerank_documents(query, documents, top_n=5):
    headers = {
        "Authorization": "Bearer YOUR_JWT_TOKEN",
        "Content-Type": "application/json"
    }
    payload = {
        "model": "wanwu-reranker-v1",
        "query": query,
        "documents": documents
    }
    response = requests.post(
        "https://api.wanwu.chinaunicom.cn/v1/rerank",
        headers=headers,
        json=payload
    )
    results = sorted(
        response.json()["results"],
        key=lambda x: x["score"],
        reverse=True
    )
    return results[:top_n]
```

### 10.3 文件加密存储方案

```
┌─────────────────────────────────────────────────────┐
│                  文件上传流程                        │
│                                                     │
│  用户上传 → 文件校验 → 敏感检测 → 加密决策 → 存储     │
│                                      │              │

│                              ↓               ↓      │
│                        敏感文件           普通文件   │
```

**加密算法选择**：

### 10.4 密钥管理方案

| 密钥类型 | 用途 | 生成方式 | 存储位置 | 轮换周期 |
|---------|------|---------|---------|---------|
| 主密钥(MK) | 加密数据密钥 | KMS生成 | 硬件安全模块(HSM) | 年度轮换 |
| 数据密钥(DK) | 加密文件内容 | 随机生成 | 加密后存储 | 文件级唯一 |
| 用户密钥(UK) | 加密用户数据密钥 | 用户生成/派生 | KMS加密存储 | 用户可控 |

**密钥层次结构**：

```
主密钥(MK) ← 存储于HSM/Cloud KMS
    │
    └── 加密 → 数据密钥(DK) ← 存储于数据库(加密状态)
            │
            └── 加密 → 文件内容 ← 存储于对象存储
```

**密钥轮换策略**：
- 主密钥：年度轮换，旧密钥保留用于解密历史数据
- 数据密钥：文件更新时重新生成
- 用户密钥：用户密码变更时重新派生
